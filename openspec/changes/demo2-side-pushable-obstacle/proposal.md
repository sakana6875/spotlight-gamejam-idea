# Demo2 SideView 可推动障碍物提案

## 背景

Demo2 已经具备 SideView 玩家移动和动态 2D 物理。输入资产中已有 `Push` 动作，但当前没有明确的可推动障碍物组件和玩家推动行为。

## 目标

1. 在 Demo2 SideView 中支持玩家按住 `Push` 持续水平推动指定障碍物。
2. 让障碍物继续使用普通动态 `Rigidbody2D`，不绕过碰撞和水体阻尼。
3. 通过一个可重复配置的场景障碍物验证完整交互路径。

## 范围

- 新增 Demo2 专用可推动障碍物组件。
- 新增 Demo2 SideView 推动控制器，读取现有 `Push` 动作。
- 为玩家提供只读朝向信息，供推动控制器使用。
- 在 `demo2` 场景中配置一个动态可推动障碍物。
- 增加推动行为的 PlayMode 验证。

## 非目标

- 不支持 TopView 推动。
- 不实现通用交互系统、接口层或跨 Demo 推动框架。
- 不实现上下推动、斜向推动、对象堆叠、抓取、投掷或吸附。
- 不修改水流的推力、浮力和阻尼合同；水仍只对实际占水格内的刚体施加速度阻尼。
- 不实现战斗、敌人、阶段完成、死亡、重试或对话流程。
- 不手工编辑 Unity 场景 YAML，不引入第三方包或新的程序集。

## 主要决策

- `Push` 使用按住持续推动语义，松开后不再施加推动力。
- 只沿玩家在 SideView 中的水平朝向推动。
- 只有显式挂载 `Demo2PushableObstacle` 的动态 `Rigidbody2D` 才能被推动，避免误推动玩家或其他物理对象。
- 推动使用 `Rigidbody2D.AddForce`，不直接修改 Transform，不用 `MovePosition` 模拟瞬移；这样保留墙体碰撞和水体阻尼的真实作用。
- 推动控制器只在玩家 Collider2D 前方的短距离 Cast 检测到可推动障碍物时施力。
- 推动检测使用预分配命中缓存，避免每个物理步创建临时数组。
- 场景实例的障碍物 Collider2D 显式接入水道移动阻挡；它只停止当前水道行，不允许触发跨行蓄积。

## 风险

- 推动力、最大水平速度和 Cast 距离会影响手感，需要在 Demo2 场景中以一个障碍物调参。
- `AddForce` 与水阻尼都运行在物理步中，最终速度取决于 Unity 脚本执行顺序和参数；验收只要求水中减速仍可观察，不锁定内部调用顺序。
- 当前玩家朝向由玩家移动控制器维护；推动控制器需要一个只读朝向契约，不能复制一套朝向状态。
