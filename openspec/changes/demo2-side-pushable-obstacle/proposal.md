# Demo2 SideView 可推动障碍物提案

## 背景

Demo2 已有按住 `Push` 主动施力的实现，但普通 Dynamic Rigidbody2D 会在玩家未按 `F` 或怪物碰撞时被动产生水平位移。现在需要保留箱子的重力掉落和动态碰撞，同时把水平移动收敛为只有玩家按住 `F` 才能授权。

## 目标

1. 在 Demo2 SideView 中仅允许玩家持续按住 `Push` 产生箱子水平移动。
2. 保留 Dynamic Rigidbody2D、Y方向重力、墙体碰撞和水体阻尼；未授权物理步冻结X位置。
3. 玩家授权推动时的水平速度固定为1米/秒，并保留当前Y速度。

## 范围

- 新增 Demo2 专用可推动障碍物组件。
- 新增 Demo2 SideView 推动控制器，读取现有 `Push` 动作。
- 为玩家提供只读朝向信息，供推动控制器使用。
- 现有障碍物继续使用 Dynamic Rigidbody2D；运行时组件负责切换水平位置约束，不自动改写场景资源。
- 更新推动行为的 PlayMode 验证。

## 非目标

- 不支持 TopView 推动。
- 不实现通用交互系统、接口层或跨 Demo 推动框架。
- 不实现上下推动、斜向推动、对象堆叠、抓取、投掷或吸附。
- 不允许重力、水流、玩家普通碰撞或怪物碰撞产生未授权的水平位移；Y方向重力掉落和既有水体阻尼继续生效。
- 不实现战斗、敌人、阶段完成、死亡、重试或对话流程。
- 不手工编辑 Unity 场景 YAML，不引入第三方包或新的程序集。

## 主要决策

- `Push` 使用按住持续推动语义；松开后的下一物理步重新冻结X位置并清零水平速度。
- 障碍物保持 Dynamic Rigidbody2D。未收到玩家请求时使用 `FreezePositionX`；收到请求时仅解除X冻结，并把水平速度设为玩家朝向的1米/秒。
- 推动只修改X速度，必须保留当前Y速度和重力。
- `Demo2PushController` 继续只在 SideView、玩家状态允许且持续按住 `F` 时提交推动请求。
- `Demo2PushableObstacle` 在比玩家控制器更晚的 FixedUpdate 中消费当步请求，避免脚本顺序造成松开后多移动一帧。
- 玩家或怪物普通碰撞没有授权请求，因此箱子保持X锁定；墙体碰撞继续由 Dynamic Rigidbody2D 物理解算。
- 障碍物 Collider2D 仍可作为水道移动阻挡，既有水体阻尼合同保持不变。

## 风险

- 推动期间箱子解除X冻结，其他碰撞仍参与物理解算；组件每个授权物理步重新设置1米/秒水平速度，避免累积加速。
- 水体阻尼可能降低箱子在水中的实际速度，这是保留既有水体合同的预期结果。
- 当前玩家朝向由玩家移动控制器维护；推动控制器需要一个只读朝向契约，不能复制一套朝向状态。
