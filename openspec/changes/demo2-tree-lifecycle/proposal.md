# Demo2 树苗生命周期提案

## 背景

Demo2 第零幕需要以中心树苗连接引水、怪物波次、啃食失败分支和最终成长结算。当前项目没有树苗运行时代码、正式树苗 Sprite 或成长 Animator，也没有正式怪物和对话运行时。若直接把刷怪、对话和通关规则写进树对象，会形成难以复用和测试的关卡超级控制器。

## 目标

1. 建立 Demo2 专用树生命周期：Dormant、Sprouting、AwaitingGrowth、Growing、Mature。
2. 树在水到达前以 Dormant 占位形态可见但碰撞体关闭；水首次到达中心后播放发芽动画并启用碰撞体。
3. 刷怪期间保持待长大状态，不播放最终成长动画。
4. 只要至少一只怪物正在啃食，按真实游戏时间累计一份啃食时长；达到20秒只通知一次。
5. 在外部关卡控制器开始结算对话时接受 `BeginGrowth()`，使用非缩放时间播放4帧成长动画。
6. 暂时使用现有 Square Sprite 作为占位视觉，后续替换正式 Sprite 时不修改状态规则。

## 范围

- 新增纯 C# 树生命周期和啃食计时规则。
- 新增 MonoBehaviour 树控制器、占位视觉和明确事实事件。
- 新增水到中心的一次性触发适配器。
- 提供怪物开始/停止攻击的显式登记入口，支持多个攻击者但不重复累计时间。
- 创建 Demo2 树苗 Prefab；场景位置和中心检测点通过 Inspector 明确配置。

## 非目标

- 不实现对话框、旁白内容、E/R 特殊台词或跳过逻辑。
- 不实现怪物生成、移动、攻击动画、死亡或左右轮换波次。
- 不统计8只怪物是否全部死亡，不自行决定通关或强制过关。
- 不修改水流、玩家攻击、视图切换、存档或场景加载。
- 不创建通用 EventBus、跨 Demo 树接口或万能关卡管理器。
- 不把占位 Square 当作正式美术资产。

## 主要决策

- 树状态规则使用纯 C# 对象，MonoBehaviour 只适配水检测、Unity 时间、SpriteRenderer 和事实事件。
- `AwaitingGrowth` 同时表示“已发芽、刷怪中、等待外部结算命令”；怪物死亡不会直接推动树状态。
- 活跃攻击者使用集合管理。集合数量大于零时，每帧只增加一次 `deltaTime`，不会按攻击者数量倍增。
- 啃食计时使用缩放时间；对话和视图转场通过现有玩法冻结使计时停止。
- Sprouting 和 Growing 占位动画使用 `unscaledDeltaTime`，保证对话期间成长动画继续播放。
- 达到20秒后发布一次 `AttackLimitReached`；是否指责玩家并强制过关由后续 Act0Controller 决定。

## 风险

- 正式 Sprite 尚未提供，占位 Prefab 只能验证状态和时序，不能作为最终视觉验收。
- 树中心世界坐标尚未在文本需求中给出，场景接线前必须明确检测点位置。
- 后续怪物系统必须在真正进入/退出攻击状态时成对登记，销毁时也必须解除，避免攻击者集合残留。
