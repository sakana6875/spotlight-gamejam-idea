# 同步进程内事件总线规格

## 1. 事件端口

### 要求：事件端口提供强类型三操作

`IEventBus` MUST 提供：

- `void Publish<TEvent>(TEvent eventData)`
- `void Subscribe<TEvent>(Action<TEvent> handler)`
- `void Unsubscribe<TEvent>(Action<TEvent> handler)`

发布者只依赖 `IEventBus` 和事件类型，不得依赖订阅者具体类型。事件类型不得携带命令方法或等待命令结果的机制。

### 要求：事件只表示事实

事件 MUST 表示已经发生的事实，使用过去时或事实名。`SessionInitializedEvent` 表示会话服务初始化已经成功完成，不负责触发初始化，也不持有服务实现。

## 2. 同步分发

### 要求：同一事件通知所有订阅者

发布没有订阅者的事件 MUST 正常返回。存在多个订阅者时，事件 MUST 在同一次 `Publish` 调用中同步通知所有订阅者，并按照成功订阅的顺序调用。

### 要求：发布期间使用稳定订阅快照

分发 MUST 允许处理器在回调期间解除自身或其他订阅者，而不会因为修改订阅列表导致枚举错误。当前发布调用使用的订阅集合应保持稳定；订阅变更影响后续发布。

### 要求：处理器异常可观察

处理器抛出的异常 MUST 传播到 `Publish` 调用方或 Unity Console，不得静默捕获、转换为成功或自动吞掉。异常发生后是否继续调用后续处理器必须由规格固定为：本阶段停止当前发布并向调用方传播，避免隐藏失败原因。

## 3. 订阅边界

### 要求：事件类型隔离

对 `TEventA` 的订阅 MUST NOT 收到 `TEventB` 的发布，即使两个事件具有相同字段或继承关系。事件总线按精确事件类型分组。

### 要求：解除订阅生效

成功解除订阅后，处理器 MUST NOT 收到后续同类型事件。重复解除不存在的处理器 MUST 不抛出异常。空处理器订阅 MUST 抛出明确参数异常；空处理器解除 MUST 安全返回。

同一个处理器重复订阅不得导致同一次发布重复通知；实现应保持现有去重行为。

## 4. 组合根与生命周期

### 要求：唯一实例由组合根创建

`SessionRoot` MUST 通过 `ISessionServiceFactory` 创建 EventBus，并将其作为 `SessionServices.EventBus` 注入使用方。其他模块不得自行创建、查找或替换全局 EventBus，不得使用静态单例或 Service Locator。

### 要求：订阅者负责解除订阅

订阅者 MUST 在场景销毁、禁用或用例结束时解除订阅。EventBus 不负责推断 Unity 生命周期，不保存业务对象列表以代替解除订阅。

## 5. 验收与非目标

EditMode 行为测试 MUST 覆盖：多订阅者和顺序、同步执行、解除订阅、事件类型隔离、异常传播、重复订阅去重，以及无订阅者发布。测试不得检查私有字段或具体容器类型。

本规格不要求网络、异步、线程安全、跨进程、持久化、事件重放或命令返回值。
