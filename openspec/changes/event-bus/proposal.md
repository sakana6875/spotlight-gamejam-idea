# 固化现有同步进程内事件总线行为

## 背景

Issue #3 已建立 `IEventBus`、`InMemoryEventBus` 和组合根注入，Issue #5 已使用 `SessionInitializedEvent` 验证初始化事件。当前没有必要再搭建新的事件架构；真正缺少的是对已有最小实现的行为边界、异常策略和测试记录。

如果现在增加通用事件目录、更多事件类型或新的抽象，会把 Game Jam 项目的当前需求扩展成未来消息系统，增加隐式依赖和维护成本。本 Issue 只把现有能力验证清楚，后续出现真实跨模块需求时再重新评估架构。

## 目标

1. 固化现有同步、进程内、强类型 EventBus 的可观察行为。
2. 用 EditMode 行为测试覆盖真实验收边界。
3. 保证 `SessionRoot` 继续创建并注入唯一 EventBus。
4. 明确事件只表达已发生事实，EventBus 不保存业务状态、不做业务决策。
5. 以最小改动完成 Issue #6，不提前创建未来场景、阶段或 Demo 事件。

## 范围

- 复核现有 `IEventBus` 三项操作：`Publish<TEvent>`、`Subscribe<TEvent>`、`Unsubscribe<TEvent>`。
- 复核现有 `InMemoryEventBus` 的同步发布、精确类型隔离、订阅顺序、重复订阅去重和异常传播。
- 保留已有 `SessionInitializedEvent`，不新增 `SceneLoadedEvent`、`StageChangedEvent` 或其他示例事件。
- 增加缺失的 EditMode 行为测试和必要的中文 XML 文档/原因注释。
- 更新本 Change 的规格、设计和验证记录。

接口、实现和事件继续使用现有程序集归属；不创建新的 Contracts 程序集，不移动已存在的生产类型，不修改 SampleScene 或正式玩法。

## 非目标

- 不新增通用事件基类、事件注册中心、过滤器、优先级或事件路由层。
- 不实现网络、跨进程、异步队列、线程安全调度、持久化或事件重放。
- 不实现命令总线、请求/响应总线或通过事件返回命令结果。
- 不新增没有真实发布者和订阅者的事件类型。
- 不修改 `SessionRoot` 的组合根职责，不创建第二个服务入口。
- 不创建正式场景、玩法事件、UI 或 Demo 业务规则。

## 风险

EventBus 处理器异常必须继续向调用方传播，不得静默吞掉。订阅者必须在生命周期结束时解除订阅。本 Issue 不解决更复杂的事件生命周期和跨线程问题；这些需求出现时必须另行评估，而不是隐式扩展当前实现。
