# 建立同步进程内强类型事件总线

## 背景

Issue #3 已通过组合根创建 `IEventBus` 和 `InMemoryEventBus` 的最小实现，Issue #5 已使用 `SessionInitializedEvent` 验证初始化事件。但事件总线目前仍缺少独立的 Issue 级行为规格、完整边界测试和订阅生命周期记录。后续模块需要发布已发生的状态事实，同时避免互相持有具体实现。

## 目标

1. 固定同步、进程内、强类型事件总线的可观察行为。
2. 验证多个订阅者、订阅顺序、解除订阅、类型隔离和异常传播。
3. 保证 `SessionRoot` 继续创建并注入唯一的 EventBus 实例。
4. 明确事件只表达已经发生的事实，EventBus 不保存业务状态、不做业务决策。
5. 为后续场景、阶段和 Demo 事件提供稳定边界，不提前实现异步或跨进程能力。

## 范围

- 复核并固化现有 `IEventBus`：`Publish<TEvent>`、`Subscribe<TEvent>`、`Unsubscribe<TEvent>`。
- 复核现有 `InMemoryEventBus` 的按事件类型索引和同步分发实现。
- 保留 `SessionInitializedEvent` 作为真实事件示例，并按需要补充最小无行为事件示例。
- 新增 EditMode 行为测试，覆盖 Issue #6 验收条件和异常可观察性。
- 更新架构 OpenSpec 与事件订阅生命周期说明。

接口继续归属 `Spotlight.Application`，具体内存实现继续归属 `Spotlight.Adapters`；不创建新的 Contracts 程序集。事件类型按实际依赖归属 Application 或 Domain，避免为了目录名称引入程序集循环。

## 非目标

- 网络、跨进程、异步队列、线程调度和持久化事件。
- 命令总线、请求/响应总线或用事件返回命令结果。
- 业务状态存储、事件重放、过滤器、优先级和重试策略。
- 修改 `SessionRoot` 的组合根职责或创建第二个全局服务入口。
- 正式场景、玩法事件和 Demo 业务规则。

## 风险

事件处理器在同步发布期间抛出的异常必须继续向调用方传播；调用方可观察失败，但本阶段不吞异常、不自动重试、不擅自继续后续处理器。订阅者必须在场景销毁或生命周期结束时显式解除订阅，否则可能造成重复通知或对象引用残留。
